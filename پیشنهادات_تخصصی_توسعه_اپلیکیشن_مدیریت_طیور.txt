۱. حالت دسترسی دوگانه: «کارگر سالن» در برابر «مالک/مدیر فارم» (Multi-User Profile)
--------------------------------------------------------------------------------
* هدف و منطق تجاری:
  امکان سپردن تبلت یا گوشی به کارگر سالن برای ثبت داده‌های روتین، در حالی که تمام ارقام مالی،
  سود و زیان، قیمت‌های خرید و فروش نهاده‌ها و تنظیمات حساس برنامه کاملاً از دید کارگر پنهان بماند.

* شِمای داده و معماری State:
  - در AppSettings:
    val isWorkerModeEnabled: Boolean = false
    val managerPinHash: String = "" // هش SHA-256 رمز ۴ تا ۶ رقمی
    val isBiometricEnabled: Boolean = true
    val autoLockTimeoutMinutes: Int = 3 // قفل خودکار در صورت عدم تحرک
  - در MainScreen / MainViewModel:
    val currentRole = mutableStateOf(if (settings.managerPinHash.isNotBlank()) UserRole.WORKER else UserRole.MANAGER)

* رفتار رابط کاربری (UI/UX Flows):
  - در حالت کارگر:
    ۱. تب «امور مالی» (FinancialScreen) و تب «تنظیمات پشتیبان‌گیری» به کلی از نوار پایین و منوی دراور حذف یا قفل می‌شوند.
    ۲. در صفحه گله‌ها و انبار، ستون‌های «قیمت واحد»، «ارزش تخمینی کل» و «تراز مالی» نامرئی می‌شوند و صرفاً مقادیر وزنی/عددی نمایش می‌یابند.
    ۳. فرم‌های ثبت دان، آب، تخم‌مرغ و تلفات به حالت «سریع و درشت» (High-Affordance Numpad) سوییچ می‌کنند.
    ۴. یک دکمه شناور با آیکون قفل 🔒 در بالای صفحه اصلی قرار دارد که با لمس آن و ورود پین یا اثر انگشت، مدیر وارد پنل کامل می‌شود.
    ۵. در صورت قفل شدن صفحه گوشی یا سپری شدن ۳ دقیقه بدون لمس، برنامه خودکار به حالت کارگر برمی‌گردد.

* پیشگیری از خطا و باگ (Edge Cases):
  - اگر مدیر پین‌کد را فراموش کند: یک کلید بازیابی اضطراری (Recovery Key) ۶ رقمی هنگام ساخت پین تولید و به کاربر نمایش داده می‌شود.
  - اعتبارسنجی مقادیر غیرعادی (Sanity Check): اگر کارگر به اشتباه برای گله ۲۰۰ قطعه‌ای عدد «۲۰۰۰ کیلو دان» را وارد کرد، سیستم دیالوگ اخطار باز می‌کند:
    «مقدار وارد شده ۱۰ برابر میانگین مصرف این گله است! آیا مطمئن هستید؟».

۲. ارتقای فرم ثبت تخم‌مرغ با تفکیک «نطفه‌دار (جوجه‌کشی)» از «خوراکی» و ثبت وزن شانه
--------------------------------------------------------------------------------
* هدف و منطق تجاری:
  تخم‌مرغ نطفه‌دار در مزارع بومی، بلدرچین و بوقلمون ۲ تا ۳ برابر تخم‌مرغ خوراکی ارزش دارد. تفکیک
  این دو و سنجش وزن، کنترل کیفی گله و برآورد دقیق درآمد را ممکن می‌سازد.

* شِمای داده و مدل Database (Entities.kt):
  data class EggProduction(
      val id: Long = 0L,
      val flockId: Long,
      val flockName: String,
      val fertileCount: Int = 0,        // تخم‌مرغ نطفه‌دار درجه یک (جوجه‌کشی)
      val tableEggCount: Int = 0,       // تخم‌مرغ خوراکی درجه یک
      val doubleYolkCount: Int = 0,     // دوزرده
      val brokenCount: Int = 0,         // شکسته / نوک‌زده
      val dirtyCount: Int = 0,          // کثیف / پوسته نرم
      val totalCount: Int = fertileCount + tableEggCount + doubleYolkCount + brokenCount + dirtyCount,
      val trayCount: Double = 0.0,      // تعداد شانه (مثلاً ۵.۵ شانه)
      val trayGrossWeightGrams: Double? = null, // وزن ناخالص شانه با پوکه
      val netEggAverageWeightGrams: Double? = null, // وزن خالص هر تخم‌مرغ
      val layingRatePercent: Double = 0.0,
      val dateJalaliStr: String,
      val timestampMillis: Long = System.currentTimeMillis(),
      val notes: String? = null
  )

* فرمول‌ها و محاسبات خودکار:
  - وزن خالص تخم‌مرغ:
    وزن استاندارد یک عدد شانه مقوایی خالی ۳۰ عددی = ۵۰ گرم.
    وزن خالص کل تخم‌مرغ‌ها = وزن ناخالص شانه - ۵۰ گرم.
    میانگین وزن هر عدد تخم‌مرغ = وزن خالص کل ÷ ۳۰.
  - نرخ نطفه‌داری تخمینی گله:
    درصد نطفه‌داری گله = (تعداد نطفه‌دار ÷ کل تخم‌مرغ‌های سالم) × ۱۰۰.

* یکپارچگی با انبارداری و امور مالی:
  - پس از ثبت، به طور خودکار دو قلم کالای تفکیک‌شده در انبار شارژ می‌شوند:
    ۱. «تخم‌مرغ نطفه‌دار گله [نام گله]» -> با قیمت بالاتر
    ۲. «تخم‌مرغ خوراکی گله [نام گله]» -> با نرخ بازار روز

  enum class MortalityReason(val titleFa: String, val isTrueMortality: Boolean) {
      DISEASE("بیماری بالینی / عفونی", isTrueMortality = true),
      HEAT_COLD_STRESS("استرس دمایی / خفگی و قطعی فن", isTrueMortality = true),
      CANNIBALISM("کانیبالیسم و خودخوری", isTrueMortality = true),
      PREDATOR_ACCIDENT("شکارچی / حوادث فیزیکی سالن", isTrueMortality = true),
      CULLING("حذف انتخابی / پرنده ضعیف یا پیر", isTrueMortality = true),
      LIVE_SALE("فروش پرنده زنده به عنوان محصول", isTrueMortality = false) // تلفات نیست!
  }

  data class FlockMortalityLog(

* نکته حیاتی جهت عدم ایجاد باگ:
  - هنگام محاسبه نرخ تلفات دوره (Mortality Rate %)، آیتم LIVE_SALE (فروش پرنده زنده) باید مستثنی شود
    چرا که فروش پرنده زنده سود مزرعه‌دار است نه تلفات گله.
  - ترسیم پای‌چارت تحلیلی: سهم هر عامل در تلفات دوره (مثلاً: ۶۰٪ استرس گرمایی، ۳۰٪ کانیبالیسم، ۱۰٪ بیماری)
    به مدیر هشدار می‌دهد که نقص از سیستم تهویه است نه واکسیناسیون.

۵. ویجت‌های اختصاصی صفحه اصلی اندروید (Android Home Screen Widgets)
--------------------------------------------------------------------------------
* هدف و منطق کاربری:
  دسترسی برق‌آسا به آمار کلیدی و اجرای سریع‌ترین عملیات فارم بدون نیاز به باز کردن کامل اپلیکیشن.

* معماری پیاده‌سازی (Jetpack Glance Compose):
  - استفاده از کتابخانه مدرن `androidx.glance:glance-appwidget` به جای RemoteViews قدیمی اندروید.
  - ویجت شماره ۱ (پایش جامع وضعیت فارم - ابعاد ۴×۲):
    نمایش تعداد کل پرندگان زنده، جمع تخم‌مرغ تولیدی امروز، دمای جاری سالن و روزهای باقی‌مانده دان در انبار.
    به‌روزرسانی کم‌مصرف از طریق WorkManager هر ۳۰ دقیقه یکبار + ارسال Broadcast آنی پس از ثبت هر داده در اپ.
  - ویجت شماره ۲ (دکمه‌های سریع ثبت سالن - ابعاد ۲×۱):
    دو دکمه بزرگ شیشه‌ای: «+ ثبت تخم‌مرغ» و «+ شارژ دان». با لمس دکمه، یک دیالوگ معلق شفاف (Transparent Dialog Activity)
    باز می‌شود که کارگر عدد را در ۲ ثانیه وارد کرده و تایید می‌کند بدون نیاز به ورود به منوهای برنامه.
  - ویجت شماره ۳ (ویجت اختصاصی دستیار صوتی هوشمند فارم - ابعاد ۱×۱ یا ۴×۱ نوار هوشمند):
    یک آیکون دایره‌ای زیبا و شناور میکروفون با هاله نورانی اکتیو (یا بار افقی شبیه Google Assistant).
    با لمس این ویجت از روی صفحه اصلی گوشی، بدون باز شدن لایوت سنگین برنامه، دیالوگ شناور دستیار صوتی (`VoiceAssistantSheet`)
    روی هوم‌اسکرین باز شده، میکروفون فوراً شروع به گوش دادن می‌کند، متن زنده گفتار را تایپ کرده، دستور را تفسیر نموده،
    کارت پیش‌نمایش را نشان می‌دهد و با تایید صوتی یا لمسی کاربر، دستور را ثبت و در کمتر از ۳ ثانیه پنجره را می‌بندد.

۶. دستیار صوتی هوشمند و جامع فارم با رونویسی زنده، تایید صوتی/لمسی و ویجت اختصاصی (Universal AI Voice Assistant)
--------------------------------------------------------------------------------
* توجیه عملیاتی و میدانی فارم:
  محیط سالن مرغداری مملو از گرد و غبار، پوشال، پر و رطوبت است؛ مرغدار یا کارگر سالن همواره دستکش کار باغبانی یا بهداشتی به دست دارد
  و دست‌هایش آلوده است. بیرون آوردن گوشی، باز کردن قفل، گشتن در منوها و تایپ کردن اعداد روی کیبورد لمسی، هم باعث کثیفی و
  خرابی گوشی می‌شود و هم در حین کار در سالن، بسیار وقت‌گیر و کلافه‌کننده است.
  با این دستیار صوتی هوشمند، کاربر می‌تواند در حال سرکشی به راهروهای سالن یا انبار، فقط با فشردن یک دکمه (یا لمس ویجت روی هوم‌اسکرین)
  و گفتن یک جمله، «هر کاری» که در اپلیکیشن قابل انجام است را کاملاً بدون دست و بدون خطا به انجام برساند.

* مولفه‌ها و ویژگی‌های کلیدی این سیستم هوشمند:

  ۱. رونویسی زنده و هم‌زمان گفتار (Real-Time Live Speech-to-Text Transcription):
     - به محض شروع صحبت کاربر، کلمات به صورت زنده و جریانی (Streamed) روی صفحه در یک کادر متنی شیشه‌ای و بزرگ تایپ می‌شوند.
     - کاربر دقیقاً در همان لحظه می‌بیند که برنامه چه کلماتی را از صدای او تشخیص می‌دهد (استفاده از متد `onPartialResults` در SpeechRecognizer اندروید).
     - نمایش انیمیشن داینامیک موج صدا (Audio Waveform Visualizer) متناسب با بلندی صدای کاربر با استفاده از متد `onRmsChanged`، تا کاربر از ضبط شدن صدایش مطمئن باشد.

  ۲. کارت پیش‌نمایش هوشمند عملیات (Smart Action Preview Card):
     - به محض پایان جمله کاربر، موتور هوشمند نیت کاربر را استخراج کرده و یک کارت ساختاریافته، بسیار تمیز و گرافیکی نمایش می‌دهد:
       ┌─────────────────────────────────────────────────────────────┐
       │ 📋 نوع عملیات: ثبت تولید تخم‌مرغ                            │
       │ 🏠 گله هدف: سالن ۱ (بومی تخم‌گذار)                          │
       │ 📦 مقدار: ۲۰ شانه (معادل ۶۰۰ دانه)                          │
       │ ⚖️ وزن کل: ۴۰ کیلوگرم (میانگین هر شانه: ۲ کیلوگرم)           │
       │ 🏷️ رده کیفی: نطفه‌دار (درجه یک جوجه‌کشی)                    │
       │ 🔄 اثر سیستمی: ذخیره در کارنامه گله + انتقال به انبار نطفه‌دار │
       └─────────────────────────────────────────────────────────────┘
       (وضعیت: منتظر پاسخ شما ... بگویید «تایید» یا دکمه را لمس کنید)

  ۳. چرخه تایید دوگانه صوتی و لمسی (Dual Voice/Touch Confirmation Loop):
     - کاربر برای تایید نیازی به لمس گوشی ندارد (ویژه دستان خاکی و دستکش‌دار)!
     - الف) تایید صوتی (Hands-Free Voice Confirmation):
       * سیستم پس از نمایش کارت، خودکار وارد حالت شنود تایید می‌شود (همراه با بوق ملایم یا اعلام صوتی کوتاه: «آیا تایید می‌کنید؟»).
       * کلمات تایید صوتی معتبر: «تایید»، «ثبت کن»، «درسته»، «بله»، «اوکی»، «انجام بده»، «حله»، «ثبتش کن»، «اره».
       * کلمات لغو صوتی معتبر: «لغو»، «نه»، «رد کن»، «کنسل»، «اشتباه شد»، «دوباره»، «پاک کن».
       * به محض گفتن «تایید»، کارت سبز شده، داده در دیتابیس ثبت و بازخورد صوتی کوتاه «ثبت شد» اعلام می‌گردد.
     - ب) تایید لمسی (Touch Fallback):
       * دو دکمه بزرگ، ارگونومیک و درشت در پایین کارت برای مواقعی که کاربر بخواهد با انگشت دکمه را لمس کند:
         [ ✓ تایید و ذخیره (دکمه بزرگ سبز رنگ) ]      [ ✕ انصراف و لغو (دکمه بزرگ قرمز رنگ) ]

  ۴. دامنه فراگیر دستورات؛ اجرای ۱۰۰٪ عملکردهای اپلیکیشن با صوت (Universal Intent Coverage):
     این سیستم به یک یا دو فرم ساده محدود نیست؛ هر کاری که کاربر می‌تواند در اپ با دست انجام دهد، با دستور صوتی قابل اجراست:
     
     الف) ثبت آمار روزانه پرورشی (Daily Production Logs):
        * تخم‌مرغ: «۱۵ شانه تخم نطفه‌دار برای سالن ۱ ثبت کن با وزن شانه ۲ کیلو»
        * تفکیک کیفیت: «امروز ۵۰ تا دانه تخم‌مرغ کثیف و ۱۰ تا شکسته در سالن ۲ داشتیم»
        * تلفات با علت علمی: «تلفات امروز سالن سه ۲ تا دانه بود به خاطر گرمازدگی» -> ثبت تلفات با تگ `HEAT_STRESS`
        * دان و آب: «۶۰ کیلوگرم میان‌دان در گله گوشتی شارژ شد» / «مصرف آب سالن بومی ۲۵۰ لیتر بود»
     
     ب) امور مالی، حسابداری و فاکتورها (Financial Invoicing):
        * ثبت درآمد: «ثبت کن: ۵ میلیون تومان از کشتارگاه بابت فروش پرنده دریافت شد»
        * ثبت هزینه: «خرید ۲ تن سویا به مبلغ ۴۰ میلیون تومان به صورت نقد با فاکتور انبار»
        * دستمزد و مساعده: «پرداخت ۳ میلیون تومان مساعده به کارگر سالن علی اکبری»
     
     ج) انبارداری و جابه‌جایی کالا (Warehouse & Inventory):
        * «۱۰ گونی کنسانتره ۲.۵ درصد به انبار دان اضافه کن»
        * «۵ کیسه گندم از انبار حواله شد به سالن ۲»
        * «موجودی فعلی ذرت در انبار چقدر است؟»
     
     د) ناوبری و انتقال سریع به صفحات (Instant Voice Navigation):
        * «برو به بخش جیره‌ساز» -> باز کردن فوری صفحه جیره‌نویسی
        * «صفحه گنجینه دانش رو باز کن» -> انتقال به دانشنامه تخصصی طیور
        * «وضعیت آب‌وهوا چطوره؟» -> باز کردن کارت و صفحه آب‌وهوای پیشرفته
        * «برو به گله سالن ۲» / «صفحه تنظیمات و پشتیبان‌گیری رو بیار»
     
     ه) استعلام و گزارش‌گیری صوتی هوشمند (Voice Queries & Analytics):
        * «امروز در کل فارم چقدر تخم‌مرغ جمع کردیم؟» -> واکشی از دیتابیس و پاسخ متنی/صوتی: «مجموع تخم‌مرغ امروز: ۱,۸۵۰ دانه»
        * «تلفات این هفته چند درصد بوده؟»
        * «سود خالص این دوره تا امروز چقدر شده؟»
        * «آیا داروی فعال با دوره پرهیز داریم؟» -> پاسخ: «بله، گله سالن ۱ واکسن فعال دارد با ۲ روز پرهیز باقی‌مانده»
     
     و) مدیریت مخاطبین تجاری و تماس مستقیم (CRM & Quick Communication):
        * «با دکتر میرزایی دامپزشک تماس بگیر» -> باز کردن مستقیم شماره‌گیر گوشی با شماره دکتر
        * «به کشتارگاه پیامک بده»
     
     ز) بهداشت، واکسیناسیون و دارودهی (Health & Treatments):
        * «واکسن قطره چشمی نیوکاسل برای گله سالن ۱ ثبت شد با ۵ روز دوره پرهیز گوشت و تخم‌مرغ»
     
     ح) ابزارها و شبیه‌سازها (Tools & Simulators):
        * «شبیه‌ساز تاریخ بهینه کشتار رو باز کن»
        * «محاسبه توجیه‌پذیری سرمایه‌گذاری برای گله جدید رو بیار»

  ۵. معماری فنی و موتور هوشمند فهم نیت (Hybrid Offline NLU & AI Engine):
     برای تضمین کارکرد ۱۰۰٪ حتی در سالن‌های بدون آنتن و اینترنت روستایی، معماری به صورت دو لایه هوشمند پیاده می‌شود:
     - لایه شنیداری (Speech-to-Text):
       استفاده از `SpeechRecognizer` بومی اندروید با پشتیبانی از زبان فارسی (`Locale("fa", "IR")`) و تنظیم
       فلگ `EXTRA_PREFER_OFFLINE = true` تا در صورت قطعی اینترنت، موتور آفلاین گوگل روی گوشی صدا را به متن تبدیل کند.
     - موتور محلی نرمال‌سازی و واژه‌شناسی (Persian Lexical Normalizer):
       تبدیل تمام حروف مشابه («ي» و «ك» عربی به فارسی)، حذف نشانه‌های نگارشی و اعراب، و تبدیل هوشمند اعداد کلامی فارسی
       به ارقام ریاضی (تبدیل «صد و بیست و پنج» به عدد ۱۲۵، تبدیل «سه و نیم کیلو» به ۳.۵، تبدیل «پنج میلیون» به ۵۰۰۰۰۰۰).
     - موتور قوانین و اسلات‌یابی محلی (Local Slot-Filling Rule Engine):
       پایگاه داده درون‌برنامه‌ای از واژگان مرغداری، اسامی گله‌ها، نژادها، انواع خوراک، واحدها (شانه، کارتن، کیلو، دانه، تن، گونی)،
       و افعال عملیاتی (ثبت کن، اضافه کن، برو به، زنگ بزن، چقدره). این موتور در کمتر از ۱۰ میلی‌ثانیه بدون نیاز به اینترنت
       دستورات استاندارد را با دقت ۹۹٪ به ساختار اکشن و پارامتر تبدیل می‌کند.
     - موتور هوش مصنوعی زبانی (LLM / On-Device or Cloud Fallback):
       در صورتی که جمله کاربر بسیار طولانی، مرکب یا دارای اصطلاحات عامیانه پیش‌بینی‌نشده باشد و اتصال اینترنت برقرار باشد،
       متن به صورت یک پرامپت فشرده به مدل زبانی ارسال شده و خروجی ساختاریافته JSON دریافت می‌گردد.
     - مجری دستورات (Action Dispatcher):
       کلاس `VoiceCommandDispatcher` اکشن تاییدشده را گرفته و مستقیماً متدهای مربوطه در Room Database (`FlockDao`، `TransactionDao`، `WarehouseDao`)
       یا کنترلر ناوبری (`NavController`) را بدون دخالت دستی کاربر فراخوانی می‌کند.

  ۶. ویجت اختصاصی صفحه اصلی (Dedicated Voice Assistant Glance Widget):
     - طراحی ویجت در هوم‌اسکرین گوشی با Jetpack Glance.
     - لمس ویجت = باز شدن دیالوگ شناور شفاف در کمتر از ۱ ثانیه، شنود زنده، نوشتن متن، نمایش کارت و ثبت با تایید صوتی.
     - کل فرآیند ثبت یا کنترل برنامه بدون باز کردن دستی هیچ منویی در عرض چند ثانیه به پایان می‌رسد.

--------------------------------------------------------------------------------
۷. تحلیل منحنی تخم‌گذاری و آلارم هوشمند افت تولید (Laying Benchmark & Drop Warning)
--------------------------------------------------------------------------------
* توجیه علمی:
  افت ۲ تا ۴ درصدی تخم‌گذاری در مراحل اولیه، پیش‌درآمد شیوع بیماری‌های ویروسی (برونشیت یا نیوکاسل گوارشی)
  یا نامتعادل بودن کلسیم/فسفر دان است که اگر ظرف ۴۸ ساعت اول مهار نشود به افت ۵۰ درصدی می‌انجامد.

* الگوریتم محاسباتی:
  - محاسبه میانگین متحرک ۳ روزه (3-Day Moving Average) برای حذف نوسانات ناشی از زمان جمع‌آوری تخم‌مرغ.
  - شرط تریگر آلارم:
    اگر `(میانگین ۳ روز اخیر) < (میانگین هفته گذشته - ۳.۵٪)` باشد:
    سیستم یک کارت هشدار پررنگ زرد/قرمز در صفحه اصلی نمایش می‌دهد:
    «هشدار افت غیرعادی تولید در گله [نام گله]: افت ۴.۲٪ نسبت به هفته پیش.
     چک‌لیست بررسی فوری: ۱. ساعات روشنایی ۲. شوری یا بوی آب ۳. کیفیت بستر و علائم خس‌خس سینه».

--------------------------------------------------------------------------------
۸. شمارشگر معکوس دوره پرهیز دارویی روی محصولات (Withdrawal Period Countdown)
--------------------------------------------------------------------------------
* توجیه بهداشتی و قانونی:
  فروش گوشت و تخم‌مرغ حاوی بقایای آنتی‌بیوتیک علاوه بر خطرات سلامتی، منجر به پلمپ فارم توسط دامپزشکی می‌شود.

* شِمای داده و پیاده‌سازی:
  - فیلد جدید در Flock:
    val medicationWithdrawalEndMillis: Long? = null
    val activeMedicationName: String? = null
  - هنگام ثبت دارو در تقویم یا بهداشت، دوره پرهیز وارد می‌شود (مثلاً ۵ روز).
  - در طول این ۵ روز:
    ۱. کنار نام گله در صفحه اصلی یک بج اخطار ⛔ «دوره پرهیز دارویی فعال» قرار می‌گیرد.
    ۲. تخم‌مرغ‌های ثبت‌شده در این بازه، با برچسب زرد «غیرقابل مصرف خوراکی» وارد انبار می‌شوند تا به اشتباه فروخته نشوند.
    ۳. شمارشگر معکوس روز و ساعت تا پایان دوره پرهیز نمایش می‌یابد.

--------------------------------------------------------------------------------
۹. شبیه‌ساز تعیین تاریخ بهینه کشتار بچ‌های گوشتی (Optimal Slaughter Date Optimizer)
--------------------------------------------------------------------------------
* توجیه اقتصادی:
  در پرندگان گوشتی (مرغ گوشتی، بلدرچین، بوقلمون)، بعد از سن مشخصی به ازای هر روز نگهداری، پرنده دان زیادی
  می‌خورد اما افزایش وزن ناچیزی دارد؛ در نتیجه سود روزانه مرغدار منفی می‌شود.

* فرمول محاسبه نقطه عطف:
  - سود حاشیه‌ای امروز = (افزایش وزن روزانه گله به کیلوگرم × قیمت زنده روز) - (کل دان مصرفی امروز × قیمت دان + هزینه‌های جاری).
  - نرم‌افزار منحنی سود حاشیه‌ای را ترسیم کرده و «پنجره طلایی ۳ روزه برای بارگیری و ارسال به کشتارگاه» را
    مشخص می‌کند تا مرغدار قبل از ورود به فاز زیان، گله را تخلیه نماید.

--------------------------------------------------------------------------------
۱۰. تقویم هشدارهای فصلی پیشگیری و بیوامنیتی (Seasonal Biosecurity Calendar)
--------------------------------------------------------------------------------
* توجیه پیشگیرانه:
  بیماری‌های مسری طیور با تغییرات فصول و مهاجرت پرندگان در تقویم سالانه الگوی تکرارشونده دارند.

* سیستم اعلانات فصلی خودکار:
  - فصل پاییز (مهر و آبان):
    آلارم هشدار مهاجرت پرندگان آبزی و خطر آنفلوآنزای فوق حاد -> دستورالعمل بستن منافذ، توری‌کشی و ضدعفونی خودروهای حامل دان.
  - فصل بهار (فروردین و اردیبهشت):
    آلارم افزایش دما و خروج مایت قرمز (کنه مرغی) و حشرات -> دستورالعمل سم‌پاشی شکاف دیوارها و زیر قفس‌ها.
  - فصل تابستان (تیر و مرداد):
    آلارم موج گرما -> چک‌لیست سرویس مه‌پاش، پوشال پد خنک‌کننده و افزودن نمک/ویتامین C به آب در ساعات خنک.

--------------------------------------------------------------------------------
۱۱. شبیه‌ساز توجیه‌پذیری سرمایه‌گذاری احداث گله (Investment Feasibility Simulator)
--------------------------------------------------------------------------------
* هدف:
  ابزاری تحلیلی برای پرورش‌دهندگانی که می‌خواهند بدانند راه‌اندازی یک گله جدید (مثلاً ۱۰۰۰ قطعه مرغ بومی یا بوقلمون)
  چقدر هزینه و چقدر سود خالص خواهد داشت.

* ورودی‌های کاربر:
  - گونه پرنده، نژاد، ظرفیت سالن (تعداد قطعه).
  - قیمت خرید هر قطعه جوجه یا نیمچه.
  - نرخ دان مصرفی (بر اساس کاتالوگ یا قیمت روز انبار).
  - هزینه پیش‌بینی‌شده انرژی و واکسیناسیون.

* خروجی‌های خودکار نرم‌افزار:
  - کل سرمایه در گردش مورد نیاز تا شروع تولید.
  - پیش‌بینی کل کیلوگرم دان مصرفی دوره.
  - تخمین درآمد ناخالص ماهیانه از فروش تخم‌مرغ یا گوشت با در نظر گرفتن ۵٪ تلفات طبیعی.
  - نقطه سر‌به‌سر (Break-Even Day) و زمان بازگشت اصل سرمایه به ماه.

--------------------------------------------------------------------------------
۱۲. همگام‌سازی ابری امن و چندکاربره (Secure Multi-Device Cloud Sync)
--------------------------------------------------------------------------------
* توجیه عملیاتی:
  مدیر فارم تمایل دارد از منزل یا شهر دیگر، آخرین وضعیت سالن را که توسط کارگر یا سرپرست مزرعه
  ثبت شده است، به صورت همگام مشاهده کند.

* پروتکل ارتباطی بدون نیاز به سرور گران‌قیمت:
  - روش اول: همگام‌سازی امن از طریق Google Drive AppData Folder (فایل پشتیبان نامرئی رمزنگاری‌شده AES-256).
  - روش دوم: اتصال مستقیم از طریق Local Wi-Fi (شبکه محلی مزرعه) بدون نیاز به اینترنت.
  - حل تعارض رکوردها (Conflict Resolution):
    ثبت فیلد `updatedAtMillis` روی تک‌تک انتیتی‌ها؛ هنگام ادغام، جدیدترین مقدار حفظ شده و تاریخچه‌ها
    در جدول دیتابیس جایگزین نمی‌شوند بلکه تجمیع می‌گردند.
